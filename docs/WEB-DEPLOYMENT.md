# Browser package and private bundled game data

The repository root is a static browser build. When the privately authorized game data has been imported into
game/, the page automatically loads game/game-index.json. Original game file names and offsets are preserved even
when physical files are split into small pieces. No runtime backend or file picker is needed for the bundled copy.

## Import the privately authorized game data

Only use this importer under the Take-Two permission the repository owner reports receiving. Keep the GitHub
repository private. Do not enable public GitHub Pages or publish, mirror, release, or advertise a site containing
these files. The root Jekyll configuration excludes game/ from generated Pages output as an additional safeguard.

From the repository root, run:

    python3 tools/web/import_game.py ~/Downloads/gtasa

The importer skips gta_sa.exe (the engine embeds the executable-derived image data it needs). Files larger than
16 MiB are split into ordinary pieces under game/.parts/; game/game-index.json maps those pieces back to their
original logical file path, size, and SHA-256 revision. The browser fetches pieces on demand and uses the existing
persistent block cache. A standard static server is sufficient; the server does not reassemble files.

Review the result before committing:

    du -sh game
    find game -type f -size +90M -print
    git status --short

No file in game/ should exceed GitHub's 100 MiB hard limit. GitHub also caps one push at 2 GiB, so a large install may
need to be committed and pushed in multiple batches. The importer reports the total size and piece count.

## Run the root site locally

From the repository root:

    tools/web/serve.sh --web . --port 8000

Open http://localhost:8000/. The project server adds the COOP/COEP headers needed for cross-origin isolation.
Those headers enable the SharedArrayBuffer bridge between the game worker and the OPFS cache. A plain
`python -m http.server` does not add them, so synchronous reads fall back to direct network requests and the
persistent cache cannot accelerate those reads. In the browser console, `crossOriginIsolated` should be `true`. The launch screen checks for the bundled game data and enables **Run Game** when the
manifest is valid. Choose **Skip intro mission** only when you want to bypass the intro; it is off by default.
Click **Run Game** to open the game in browser fullscreen. The engine's default bindings are Left Shift to sprint and Space to jump (the browser passes physical key
scan codes through unchanged); vertical mouse movement is inverted, and **0** toggles the engine log. The HUD retains cache download, mute/volume,
Full window, Fullscreen, and Exit game controls. A folder picker is available under "Use a different
GTA San Andreas folder" as a fallback. Do not open the HTML through file://: browser module workers and WebAssembly
require an HTTP(S) origin.

## Build and preview the editable web source

The checked-in web/ directory is the editable frontend source; the WebAssembly glue and binary are generated by Rust.
After changing Rust game code (including the default keyboard bindings), rebuild and mirror the runtime into the
repository root with:

    tools/web/export-root.sh

This runs the wasm32 release build and wasm-bindgen, then copies the updated `web/pkg/` output into root `pkg/`.
Commit the generated `pkg/sa_game.js` and `pkg/sa_game_bg.wasm` along with the source change. Running
`tools/web/build.sh` alone updates only `web/pkg/`, not the root browser package.

The standard development page in web/ can still be served with:

    tools/web/serve.sh

The same launch screen is used there. From a repository checkout it also checks ../game/game-index.json; when
running a standalone development build without bundled data, expand "Use a different GTA San Andreas folder"
and select a local game folder.

## Privacy and deployment

Do not deploy this repository's root to a public website. The user-reported Take-Two permission is conditional on
keeping the files nonpublic and not advertising any hosted website. GitHub Pages from a private personal repository
is public by default; the root Jekyll exclusion is only a safeguard, not permission to publish. Keep the repository
private and use a local HTTP server for the intended workflow.

The browser runtime also includes executable-derived data compiled into pkg/sa_game_bg.wasm; the repository must
remain private while that data is present.
