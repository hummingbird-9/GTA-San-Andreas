# Browser package and deployment

The browser version is the recommended entry point. The checked-in `web/` directory is the frontend source; the
WebAssembly glue and binary are generated by Rust and are deliberately ignored by Git.

## Build a complete static package

From the repository root:

```sh
tools/web/package.sh
```

This runs `tools/web/build.sh` and creates `dist/`, with `index.html` at the package root. It includes the page,
module worker, loader, audio worklet, and `pkg/sa_game.js` / `pkg/sa_game_bg.wasm`. The package is self-contained
except for the player's own GTA San Andreas PC 1.0 US data files.

`dist/` is generated output and is git-ignored. Do not commit it into the source history.

## Preview locally

```sh
tools/web/serve.sh --web dist
```

Open <http://localhost:8642/>. Select the directory that contains `models/gta3.img`. The browser reads the chosen
files locally; they are not uploaded to the host. Do not open the HTML through `file://`: module workers and
WebAssembly need an HTTP(S) origin.

For development, the original source-tree server still works:

```sh
tools/web/build.sh
tools/web/serve.sh
```

## Download a built package

The private repository has a manual GitHub Actions workflow named **Build browser package**. Run it from the
Actions tab, then download the `sa-engine-web-package` artifact from the completed run. The artifact is a ZIP
of `dist/`; extract it and serve the extracted directory over HTTP(S).

The workflow only creates a private Actions artifact. It does not publish a website or enable Pages.

## Static hosting

The contents of `dist/` form a static website. Upload the *contents* of that directory to the document root of a
static host that serves JavaScript modules and WebAssembly (the WASM MIME type should be
`application/wasm`). The generated `_headers` file is read by Cloudflare Pages and enables cross-origin
isolation for the lower-latency shared audio ring. On hosts that do not support custom headers, the frontend falls
back to audio message passing and IndexedDB; it does not require the host to serve the user's GTA folder.

A GitHub Pages build would also need to publish the generated `dist/` output, not the source repository root.
**Do not publish this package to a public website while it contains the built-in image data.** See the next section.

## Important: keep the package private

The `sa-image` crate embeds data extracted from the GTA executable, and the repository's project rules require
the repository to remain private while it contains those generated bytes. Those bytes are compiled into
`pkg/sa_game_bg.wasm`; publishing the WASM publicly would expose them even though the source repository is private.

GitHub Pages sites from private repositories are public by default unless the repository belongs to an organization
using GitHub Enterprise Cloud with private Pages access control. A personal private repository does not make its
Pages output private. For that reason this repository intentionally has **no automatic GitHub Pages deployment**.
The manual Actions workflow provides a private download artifact instead.

For a remotely hosted playable site, use a host with authentication in front of the entire site (for example,
Cloudflare Access) and keep access restricted to people you authorize. Do not put the game installation itself on
the host; players choose their local copy in the browser.
